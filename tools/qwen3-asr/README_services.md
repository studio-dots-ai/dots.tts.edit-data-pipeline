# Qwen3-ASR and Qwen3 Forced Aligner Service

## Overview

Qwen3-ASR model package plus service entrypoints used by this repo. Supports:

- **Speech Recognition**: Transcribe speech to text in 52 languages and dialects
- **Language Identification**: Automatically detect the spoken language
- **Timestamp Alignment**: Standalone forced alignment via `Qwen/Qwen3-ForcedAligner-0.6B`

**Repository environments**:
- `envs/pipe-asr` for the standalone Qwen3 forced aligner HTTP service
- `envs/pipe-asr` or `envs/pipe-gpu` for Qwen3-ASR usage depending on backend

**Ports**:
- `8028` — standalone Qwen3 Forced Aligner service
- ASR port is determined by caller; the repo-wide ASR gateway is `tools/asr-service/` on `8010`

**Models**:
- `Qwen/Qwen3-ASR-1.7B` — main ASR model
- `Qwen/Qwen3-ASR-0.6B` — lightweight ASR model
- `Qwen/Qwen3-ForcedAligner-0.6B` — timestamp alignment

## Usage

```bash
source envs/pipe-asr/.venv/bin/activate
cd tools/qwen3-asr
```

### Python API

```python
import torch
from qwen_asr import Qwen3ASRModel

model = Qwen3ASRModel.from_pretrained(
    "Qwen/Qwen3-ASR-1.7B",
    dtype=torch.bfloat16,
    device_map="cuda:0",
)

results = model.transcribe(
    audio="path/to/audio.wav",
    language=None,  # Auto-detect
)

print(results[0].text)
```

### vLLM Backend (Recommended for Production)

```python
from qwen_asr import Qwen3ASRModel

if __name__ == '__main__':
    model = Qwen3ASRModel.LLM(
        model="Qwen/Qwen3-ASR-1.7B",
        gpu_memory_utilization=0.7,
    )

    results = model.transcribe(audio=["path/to/audio.wav"])
    print(results[0].text)
```

### Launch ASR Server

```bash
qwen-asr-serve Qwen/Qwen3-ASR-1.7B --gpu-memory-utilization 0.8 --host 0.0.0.0 --port 8000
```

### Launch Standalone Forced Aligner Service

```bash
CHECKPOINTS_DIR=/path/to/model-cache envs/pipe-asr/.venv/bin/python \
    tools/qwen3-asr/forced_alignment_service.py \
    --port 8028 \
    --model "/path/to/model-cache/Qwen3-ForcedAligner-0.6B"
```

## Endpoints

### Qwen3-ASR

| Method | Path | Description |
|--------|------|-------------|
| POST | `/v1/chat/completions` | OpenAI-compatible ASR API |

### Standalone Qwen3 Forced Aligner Service

| Method | Path | Description |
|--------|------|-------------|
| GET | `/health` | Service health and model-loaded status |
| GET | `/info` | Model/config metadata |
| GET | `/supported_languages` | Supported language names |
| POST | `/preview_units` | Show how the transcript will be tokenized for alignment |
| POST | `/align` | Single alignment request |
| POST | `/align_batch` | Batch alignment request |

`/preview_units` returns the exact alignment units generated by the local Qwen wrapper. `/align` requires explicit language names like `English` or `Chinese` and supports `word_level=true`: space-delimited languages report `level="word"`, while Chinese reports `level="char"` because the existing Qwen units are already Han-character aligned. Alignment items are returned as `{char, start, end, is_punctuation}`; the old duplicate `text` field is no longer included. `/align` and `/align_batch` also accept optional CTC-style tagged `queries`; when present, the response includes `answers` plus a response-level `query_tokenization_matches_default` flag indicating whether the query-boundary-forced tokenization matches default Qwen tokenization for the plain text.

Typical `/align` request fields: `audio`, `text`, `language`, optional `word_level`, and optional `queries`. CTC-style `separate_punctuation`, `debug`, and `debug_dir` remain unsupported and must stay unset/false. Typical response fields: `status`, `backend`, `language`, `level`, `num_chars`, `alignments`, and when `queries` is present also `answers` and `query_tokenization_matches_default`.

## Features

- **Batch Inference**: Process multiple audio files in parallel
- **Streaming Support**: Real-time transcription (vLLM backend only)
- **Timestamp Output**: Word/character-level alignment
- **Multi-language**: 52 languages and dialects supported
- **Previewable tokenization**: The standalone aligner service exposes `/preview_units` for debugging unit granularity

## Notes

- Requires vLLM for optimal performance
- FlashAttention 2 recommended for faster inference
- A compatible GPU with enough memory for the selected model and batch size
- The standalone forced aligner uses the Transformers backend and does not require vLLM

## Official source layout

The service wrapper lives in this directory; `upstream/` pins the official source. Initialize that submodule before launching. Reuse an existing uv interpreter by absolute path in a new worktree. The service activates and verifies this checkout before importing model code, so a previous editable installation cannot silently supply the implementation. Pinned source revisions and patches are recorded in `upstream.json`; regression contracts live in `tests/`.
