# Boundary Pause Smoother

## Processing model

### What This Service Does

Boundary Pause Smoother supports two point modes:

- `smooth_only`: regenerate a seam-centered span around `position_sec`
- `adjust`: resolve or consume a native pause interval, optionally shrink or
  expand that pause, then regenerate around the adjusted pause

For normal `adjust` requests without `audio_insert`, the service uses one
continuous F5-TTS edit region:

```text
| left context | adjusted pause | right context |
  <----- regen_margin -----><---- regen_margin ----->
<---------------- one continuous edit region ---------------->
```

For `audio_insert` requests, the service uses a different semantics for
`regen_margin_sec`, and it can optionally expose a small amount of real speech
near the insert boundaries to F5 via `audio_insert_intrusion_ratio`.

```text
| left context | left speech regen | insert interval | right speech regen | right context |
                 <--- regen_margin --->                  <--- regen_margin --->
```

In `audio_insert` mode:

- the adjusted pause duration is exactly the insert audio duration
- `regen_margin_sec` means the left and right speech-transition duration to
  regenerate with F5-TTS
- `audio_insert_intrusion_ratio` controls how much of the insert duration is
  exposed at the left and right insert edges during F5 boundary regeneration,
  from `0.0` to `0.5` per side
- the insert interval itself is not regenerated by F5-TTS; it is overwritten by
  `audio_insert` after smoothing

### Core Execution Model

#### 2.1 Point normalization

Every request point is normalized to a `position_sec`.

- `smooth_only`: `position_sec` is required
- `adjust`: if `pause_interval_sec` is given, `position_sec` becomes the
  interval midpoint

#### 2.2 Native pause interval resolution

For `adjust` mode:

- if `pause_interval_sec` is supplied, the service trusts it directly
- otherwise it resolves the interval from aligner + VAD

#### 2.3 Pause adjustment

Without `audio_insert`, the service clamps the native pause into the requested
`min_pause_sec` / `max_pause_sec` range.

With `audio_insert`, the service ignores caller-supplied pause bounds and sets:

```text
adjusted_pause_duration = audio_insert_duration
```

#### 2.4 F5 regeneration layout

Without `audio_insert`:

```text
edit_start = adjusted_pause_start - regen_margin_sec
edit_end   = adjusted_pause_end   + regen_margin_sec
```

With `audio_insert`:

```text
left_edit  = [adjusted_pause_start - regen_margin_sec, adjusted_pause_start]
right_edit = [adjusted_pause_end, adjusted_pause_end + regen_margin_sec]
insert     = [adjusted_pause_start, adjusted_pause_end]
left_intrusion_end    = adjusted_pause_start + insert_duration * audio_insert_intrusion_ratio
right_intrusion_start = adjusted_pause_end   - insert_duration * audio_insert_intrusion_ratio
```

The actual conditioning audio sent to F5-TTS zeroes only the forced-silence
insert interval:

- insert interval

The left and right speech-regeneration spans, including any intrusion exposed by
`audio_insert_intrusion_ratio`, remain unchanged in `02_f5_input.wav` and are
edited solely through the F5 mask. The service still overwrites the full insert
interval with `audio_insert` in the final output.

### Dependency Model

- `smooth_only`: depends only on F5-TTS
- `adjust` with explicit `pause_interval_sec`: depends only on F5-TTS
- `adjust` without `pause_interval_sec`: depends on aligner + VAD + F5-TTS

### Pipeline Architecture

#### Regen-only fast path

1. Build regen spans from `position_sec ± regen_margin_sec`
2. Merge overlapping spans
3. Single F5-TTS mask-prediction call with `preserve_unmasked_waveform=true`
4. F5-TTS returns a waveform-preserved splice with 20ms in-region crossfade

#### Full pause-processing path (single-pass)

1. **Qwen3 Alignment (once)** — Word-level alignment, run once on original audio
2. **VAD (once)** — Voice Activity Detection on original audio; silence gaps shrunk by 0.05s each side
3. **Per-point pause detection** — For each point: find pause from alignment, refine with VAD overlap intersection
4. **Plan all trims** — Collect cut regions (trim/clamp decisions) for all points upfront
5. **Apply trims right-to-left** — Batch trim to avoid position drift (right-side trims don't affect left positions)
6. **Map junction positions** — Use cumulative offset math to locate junctions in post-trim audio
7. **Merge regen spans** — Construct regeneration spans around junctions, merge overlapping ones
8. **Single F5-TTS call** — One mask-prediction call with all `edit_spans_sec` for all junctions
9. **Waveform-preserved output** — F5-TTS splices regenerated regions into the original/current waveform with 20ms in-region crossfade and preserves the input sample rate

#### Key Design Decisions

- **Automatic mode detection** from point parameters — no explicit mode flag needed
- **Single alignment + single VAD** avoids cascading errors from repeated calls on modified audio
- **Batch trims right-to-left** keeps position math simple (positions left of a trim are unchanged)
- **Merged regen spans** minimize F5-TTS masked area (smaller masks = higher quality)
- **VAD refinement** (0.05s shrink) prevents clipping speech edges
- **`regen_margin_sec`**: optional. When omitted, the service derives a request-wide margin using `max(0.4, min(duration_sec / 7, 1.2))`. Explicit numeric values are still supported as manual overrides.

## API reference

### Request Contract

Top-level request:

```python
{
    "audio": {"data": "<base64>", "format": "wav"},
    "text": "Full transcript corresponding to the audio",
    "points": [...],
    "f5_steps": 32,
    "f5_cfg_strength": 2.0,
    "f5_sway_sampling_coef": -1.0,
    "f5_seed": 42,
    "output_format": "wav",
    "debug": False,
    "debug_dir": None,
    "trace_id": None,
}
```

Per-point schema:

```python
{
    "mode": "adjust",
    "position_sec": 1.5,
    "pause_interval_sec": [1.45, 1.55],
    "min_pause_sec": 0.0,
    "max_pause_sec": 0.3,
    "regen_margin_sec": 0.15,
    "audio_insert_intrusion_ratio": 0.2,
    "audio_insert": {"data": "<base64>", "format": "wav"},
}
```

Field semantics:

- `regen_margin_sec`
  - normal `adjust`: extra context on each side of the adjusted pause
  - `audio_insert` mode: left/right speech transition duration to regenerate
- `audio_insert`
  - optional in `adjust` mode only
  - when present, its duration becomes the adjusted pause duration
- `audio_insert_intrusion_ratio`
  - optional in `audio_insert` mode only
  - must satisfy `0.0 <= audio_insert_intrusion_ratio <= 0.5`
  - `0.0` keeps the legacy behavior with a fully zeroed insert interval in F5
    conditioning
  - `0.2` is the current recommended starting point for beep-style
    `audio_insert` demos because it was the smallest value that restored all 6/6
    sweep transcripts while avoiding the larger context edits of `0.3` and
    `0.4`

### Validation Rules

- `mode="smooth_only"` requires `position_sec`
- `mode="smooth_only"` must not provide `pause_interval_sec`, `min_pause_sec`,
  `max_pause_sec`, or `audio_insert`
- `mode="adjust"` must provide at least one of `position_sec` or
  `pause_interval_sec`
- if both `min_pause_sec` and `max_pause_sec` are provided without
  `audio_insert`, they must satisfy `min_pause_sec <= max_pause_sec`
- `audio_insert` is valid only in `adjust` mode
- `audio_insert_intrusion_ratio` is valid only when `audio_insert` is present
- `audio_insert_intrusion_ratio` must satisfy `0.0 <= value <= 0.5`
- `regen_margin_sec` must satisfy `0.05 <= regen_margin_sec <= 1.0`

### Debug Artifacts

When `debug=true`, the service writes:

- `00_original.wav`: original input
- `01_pause_adjusted.wav`: pause-adjusted waveform before F5 preparation
- `02_f5_input.wav`: actual waveform sent to F5-TTS as `cond`
- `03_mask_visualization.wav`: debug visualization with all edit spans zeroed
- `04_f5_output.wav`: F5 waveform-preserved splice output at the request sample rate
- `05_smoothed.wav`: post-splice waveform before insert overwrite
- `06_audio_inserted.wav`: final waveform after insert overwrite (audio_insert mode only)
- `debug_info.json`: normalized config, resolved spans, and per-point details

`debug_info.json` records:

- `regen_spans_merged`
- `protected_intervals`
- `points_config`
- per-point `audio_insert_interval` or `regen`
- per-point `audio_insert_intrusion`

### Example

Explicit pause insertion with audio insert:

```python
{
    "audio": {"data": "<base64>", "format": "wav"},
    "text": "Monday, there's, gonna be haze, but Tuesday, look for thunderstorms.",
    "points": [
        {
            "mode": "adjust",
            "pause_interval_sec": [1.428, 1.512],
            "regen_margin_sec": 0.4,
            "audio_insert_intrusion_ratio": 0.2,
            "audio_insert": {"data": "<base64 sound event>", "format": "wav"},
        }
    ],
    "f5_steps": 32,
    "output_format": "wav",
    "debug": True,
}
```

### Function API

```python
from smoother import smooth_audio, SmoothingPoint

result = smooth_audio(
    audio=waveform,        # np.ndarray float32
    sample_rate=22050,
    text="Full text",
    points=[SmoothingPoint(position_sec=1.5, remove_pause=True)],
    f5tts_url="http://localhost:8001",
    aligner_url="http://localhost:8029",
    vad_url="http://localhost:8005",
    debug=True,
    debug_dir="/path/to/artifacts/boundary_pause_smoother/debug",
)
# result.audio: smoothed waveform
# result.details: per-point processing info
```

### Failure behavior

Alignment and VAD failures propagate to the request. If valid alignment/VAD results contain no native silence at an insertion boundary, the requested pause is inserted at that boundary.
